# Step 01 — The virtual machine

Everything runs on one Linux VM. This step sizes it, gives it a fixed address,
and records the two settings every later step depends on.

If your VM is already up and reachable over SSH, skip to [1.2](#12-verify-the-specs).

## 1.1 Create the VM

Any hypervisor works — Proxmox, ESXi, Hyper-V, UTM, VirtualBox, or a cloud
instance. The guide was written on Proxmox, but nothing in it is
Proxmox-specific.

| Resource | Value | Why |
|---|---|---|
| vCPU | 8 | sbt and Maven builds are the bottleneck |
| RAM | 24 GB | ~16 GB measured for the running stack, ~1 GB for k3s, 4 GB+ headroom for JVM builds |
| Disk | 150 GB | 13 container images, the registry, and Go/npm/sbt/Maven caches |
| OS | Ubuntu 24.04 LTS or Debian 12 | well-trodden for k3s |
| CPU arch | **x86_64** | every published `ghcr.io/eegfaktura/*` image is amd64-only |

Also enable the guest agent (`qemu-guest-agent` on Proxmox) and set up SSH key
authentication before you start.

> [!TIP]
> **Use a VM, not an LXC container.** k3s inside LXC needs cgroup and AppArmor
> workarounds that are a poor use of an afternoon.

You can go smaller than 24 GB by skipping the two optional JVM services in
[step 17](17-billing-eda.md) and building images one at a time, but 16 GB is a
realistic floor. Below that, the Scala builds fail late and confusingly rather
than early and clearly.

## 1.2 Verify the specs

```bash
nproc
free -g
df -h /
lsb_release -a
uname -m
```

`uname -m` must print **`x86_64`**. That is the whole point of building here:
the upstream images are single-arch amd64 (see
[known problems #1](known-problems.md#1-published-images-are-amd64-only)), and
on Apple Silicon they need Rosetta emulation.

## 1.3 Record your settings

Two values recur in nearly every command from here on. Decide them now and put
them in your shell profile, so every later command can be pasted unchanged.

- **`VM_IP`** — the address this VM will keep. Pin it in the next section.
- **`BASE_DOMAIN`** — a domain **you control**, under which the three service
  hostnames will live. It does not need to be public or internet-reachable, but
  you must be able to add DNS records for it, because [step 05](05-tls.md) uses
  a DNS-01 ACME challenge to get a real certificate.

Substitute your own two values into the first two lines:

```bash
cat >> ~/.bashrc <<'EOF'

# --- eegfaktura-k3s ---
export VM_IP=192.168.1.50
export BASE_DOMAIN=dev.yourdomain.com
export KC_HOST="keycloak.$BASE_DOMAIN"
export APP_HOST="app.$BASE_DOMAIN"
export ADMIN_HOST="admin.$BASE_DOMAIN"
export KC="https://$KC_HOST"
export K8S="$HOME/eegfaktura-k3s/k8s"
EOF
source ~/.bashrc
```

```bash
echo "$VM_IP  $BASE_DOMAIN  $KC_HOST  $APP_HOST  $ADMIN_HOST"
```

> [!IMPORTANT]
> `BASE_DOMAIN` is baked into Keycloak's token issuer, into both frontends, and
> into the TLS certificate. Changing it later means redoing steps 05, 11 and 12.
> Pick it once.

Throughout this guide, `dev.yourdomain.com` stands for whatever you chose.
Shell commands use `$BASE_DOMAIN` and can be pasted as-is; prose and browser
URLs spell out the placeholder.

## 1.4 Pin the IP address

The hostnames in [step 02](02-domain-and-dns.md) map to this address by hand, so
it must not change. Either reserve it in your DHCP server, or configure it
statically. On Ubuntu with netplan:

```bash
ip -br link
```

```bash
sudo nano /etc/netplan/50-cloud-init.yaml
```

Use the interface name that `ip -br link` reported (often `ens18` on Proxmox,
`eth0` elsewhere), your address, and your gateway:

```yaml
network:
  version: 2
  ethernets:
    ens18:
      dhcp4: false
      addresses: [192.168.1.50/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [192.168.1.1]
```

```bash
sudo netplan apply
ip -4 addr show scope global | grep inet
```

> [!NOTE]
> Point `nameservers` at your **LAN resolver**, not at a public one like
> `1.1.1.1`. Step 02 adds the service hostnames to that resolver, and pods
> inherit the VM's resolver — so a public-only DNS setting means pods cannot
> resolve Keycloak. [Step 11](11-keycloak.md) has a fallback if you cannot
> change it.

## 1.6 Timezone

The stack assumes Central European semantics for billing periods, and the
backend image sets `TZ=Europe/Berlin` internally. Matching the host keeps log
timestamps comparable:

```bash
sudo timedatectl set-timezone Europe/Vienna
timedatectl
```

## 1.7 Firewall

If `ufw` is active, open what k3s and the ingress need:

```bash
sudo ufw status
```

<details>
<summary>Only if <code>ufw</code> reports <code>active</code></summary>

```bash
sudo ufw allow 6443/tcp   # Kubernetes API
sudo ufw allow 80/tcp     # ingress, and the HTTP→HTTPS redirect
sudo ufw allow 443/tcp    # ingress
```

</details>
