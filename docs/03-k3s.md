# Step 03 — Install k3s

k3s is a single binary that bundles everything the docker-compose stack needs an
analogue for: containerd, CoreDNS, **Traefik** (ingress), **local-path**
(so `PersistentVolumeClaim` works with no extra setup) and metrics-server. That
keeps the focus on the build pipeline rather than on assembling a cluster.

## 3.1 Install

```bash
curl -sfL https://get.k3s.io | sh -s - --write-kubeconfig-mode 644
```

```bash
sudo systemctl status k3s --no-pager
```

```bash
kubectl get nodes
```

```
NAME      STATUS   ROLES                  AGE   VERSION
k8s-dev   Ready    control-plane,master   30s   v1.3x.x+k3s1
```

## 3.2 Give yourself a writable kubeconfig

k3s installs its own `kubectl` and points `KUBECONFIG` at a root-owned file.
Copy it somewhere you own:

```bash
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown "$USER:$USER" ~/.kube/config
chmod 600 ~/.kube/config
```

```bash
echo 'export KUBECONFIG=$HOME/.kube/config' >> ~/.bashrc
source ~/.bashrc
kubectl get nodes
```

> [!WARNING]
> **Do not leave `KUBECONFIG` pointing at `/etc/rancher/k3s/k3s.yaml`.**
> `--write-kubeconfig-mode 644` makes that file *readable*, not writable, and
> its directory stays root-owned. Read-only commands work, so the problem only
> surfaces later, at the first command that writes config — such as switching
> namespace in [step 09](09-namespace-and-secrets.md):
> ```
> error: open /etc/rancher/k3s/k3s.yaml.lock: permission denied
> ```
> kubectl needs to create a lock file beside the config. The copy above avoids
> this permanently.

## 3.3 Confirm the bundled components

```bash
kubectl get pods -A
```

Expect `coredns`, `local-path-provisioner`, `metrics-server`, `svclb-traefik-*`
and `traefik` in `kube-system`, all `Running`.

```bash
kubectl get ingressclass
kubectl get storageclass
```

`traefik` and `local-path` (marked `default`) respectively.

## 3.4 Prove ingress and DNS end to end

Do this before touching eegfaktura. It validates DNS, Traefik and routing in one
shot, so every later failure has one fewer possible cause.

```bash
kubectl create deployment smoketest --image=nginx
kubectl expose deployment smoketest --port=80
kubectl create ingress smoketest --class=traefik --rule="$APP_HOST/*=smoketest:80"
```

```bash
kubectl rollout status deployment/smoketest --timeout=120s
```

```bash
curl -s "http://$APP_HOST" | head -5
```

Then from your **workstation's browser**: `http://app.dev.yourdomain.com` — the
nginx welcome page.

> [!NOTE]
> This is plain HTTP on purpose. TLS arrives in [step 05](05-tls.md); right now
> the question is only whether name → Traefik → Service works at all.

Clean up:

```bash
kubectl delete ingress smoketest; kubectl delete service smoketest; kubectl delete deployment smoketest
```

<details>
<summary>If the smoke test fails</summary>

| Symptom | Cause |
|---|---|
| `could not resolve host` | DNS. Redo [step 02](02-domain-and-dns.md) — the name does not resolve where you ran `curl` |
| Connection refused / timeout | Traefik is not listening, or a firewall blocks 80. `kubectl get svc -n kube-system traefik` should show an external IP; check `sudo ufw status` |
| `404 page not found` | Reached Traefik, but no router matched. The `--rule` hostname must be exactly the name you browsed to |
| `503` | Router exists, no ready endpoint. `kubectl get pods` — nginx is probably still pulling |

</details>

> [!CAUTION]
> Do not continue until this passes. Every later service is reached through this
> same path, and debugging Keycloak's token issuer while ingress is quietly
> broken is a bad afternoon.

## 3.5 kubectl from your workstation (optional)

Handy for `kubectl logs` and `kubectl get` without an SSH session. Everything in
this guide runs fine on the VM alone, so this is convenience only.

```bash
# on your workstation
brew install kubectl          # or your package manager
mkdir -p ~/.kube
scp <user>@<vm-ip>:~/.kube/config ~/.kube/eegfaktura.yaml
sed -i '' "s/127.0.0.1/<vm-ip>/" ~/.kube/eegfaktura.yaml   # GNU sed: drop the ''
export KUBECONFIG=~/.kube/eegfaktura.yaml
kubectl get nodes
```

> [!NOTE]
> The embedded server URL is `https://127.0.0.1:6443`, which is only correct *on*
> the VM. The `sed` rewrites it. The server certificate already carries the node
> IP as a SAN, so TLS validates without further work.

## Done when

- The nginx page loaded in your browser over `app.dev.yourdomain.com`
